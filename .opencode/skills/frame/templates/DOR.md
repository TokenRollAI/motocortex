产出 `DOR.md` 时照这个骨架填。把每条填成本项目的具体条目,不要留占位文字。已满足的勾上,缺的标 blocker。

# DOR(Definition of Ready)

> 开工前的就绪风险清单。已满足的勾上;未满足的不阻止开工,而是作为 blocker 继承进
> PROGRESS——它缩小 agent 本次能推进的范围(依赖它的 DoD 项会被跳过),而不是让整件事停摆。
> 目标是让 agent 带着"什么还没就绪"的清醒认知开跑,而不是在门口空等。

## 需求就绪
- [ ] VISION 的成功标准都可验收(每条能被命令或 User Case 检验)
- [ ] 没有静默假设(grill 记录在案的假设都已被用户追认)

## 技术就绪
- [ ] 技术栈已确定(已定型的记录在案;新选的写明理由)
- [ ] 构建 / 测试 / 运行的命令已知且可跑

## 外部前置就绪
- [ ] 需要的凭据 / 账号 / 外部服务已就位(逐条列,缺的标 blocker)
- [ ] 依赖的上游 / 环境已可访问

## 验收手段就绪
- [ ] 每个 User Case 都能写出对应的可重跑验收命令
