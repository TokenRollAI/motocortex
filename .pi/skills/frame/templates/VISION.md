# VISION 模板

产出 `VISION.md` 时照这个骨架填,每一节都要填满。这是要照抄的结构,不是散文。

<vision-template>
# Vision

> 一句话:这个项目是什么、为谁解决什么。

## 要解决的问题

<用户当前的痛点,来自 grill 的共识>

## 要做什么

<系统是什么;核心主张;必要时给一张边界示意>

## 非目标

<明确不做什么——防止 scope 蔓延>

## 成功标准

<可验收的判据。每一条都要具体到能被一条命令或一个 User Case 检验。
 不可验收的成功标准等于没写。>

## User Case(验收基准)

<把成功标准拆成 N 个具体场景,每个是"用户做了什么 → 得到什么"。
 这些 Case 后面会一一对应 DOD 的 E2E 验收项。>

### Case 1:<名字>

1. <步骤>
2. <步骤>
3. <得到什么>

### Case 2:<名字>

...
</vision-template>
