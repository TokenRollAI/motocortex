# LOOP(持续开发执行契约)

> 本文与 DOD.md 是一对:DOD 定义什么算完成,本文定义每一轮怎么干。
> 这是无人值守(AFK)契约:没有人在每轮之间把关,所以证据门、晋级与终止条件都写死在下面。

## 如何启动

把下面这段粘进一个 agent 会话(或用 `/goal`,若已安装为命令):

```
读本仓库的 LOOP.md 与 PROGRESS.md,按 LOOP.md 的状态机一轮接一轮地跑,
直到命中终止条件。每轮结束把证据与勾选写进 PROGRESS.md。
你被授权自动编辑文件;commit 与其它外向动作按 LOOP 的纪律与宿主惯例判断。
```

一次能连跑几轮取决于宿主:有的 harness 一次回复只跑一轮,那就反复重入(手动"继续"、脚本或外层 loop)。本文只保证——不管谁来唤起,行为都一致、且知道何时该停。

## 不可违背的纪律
1. **DOD 是法官**:只有可复现证据(命令 + 输出,或等价的可重跑判据)能勾选 DoD 项。没跑过、没贴证据,就不勾。
2. **不伪造进度**:失败就报告失败,跳过就明说跳过。
3. **规格是宪法**:实现偏离 VISION/文档时,先改文档说明理由,再写码。
4. **成熟框架优先**:要从头造轮子时先停下找现成方案。

## 按宿主能力调整(不是铁令,用判断)
- **commit**:默认少量多次提交;但先看工作区是否干净、用户是否授权 commit。未授权就把变更留着、在 PROGRESS 记一笔,别自作主张提交。
- **subagent**:界限清晰的子任务派并行 subagent 加速;宿主不支持就顺序自己做。
- **回归**:每轮跑与本项相关的验证;全量回归成本可接受就每轮跑,过重则在 Phase 晋级时跑一次全量。

## 每一轮
1. 取 context:读 PROGRESS.md(当前 Phase、上轮遗留、blocker)+ DOD 当前 Phase。
2. 定目标:挑当前 Phase 一个未勾选、且不被 blocker 卡住的 DoD 项作为本轮唯一目标。
3. 实现:见"按宿主能力调整"。
4. 验证:拿到本项的可复现证据。把命令与输出贴进 PROGRESS,再勾 DoD。
5. 沉淀:更新 PROGRESS;踩了坑记下来防止下轮重蹈。

## 状态机:晋级与终止
每轮结束后判断下一步:
- **Phase 晋级**:当前 Phase 的 DoD 项全部勾选(E2E 那条 Phase 则是每条 E2E 都勾选)→ 跑一次该 Phase 全量回归,证据入 PROGRESS → 进入下一 Phase。不跳 Phase。
- **全部完成(终止)**:最后一个 Phase(E2E)全勾 → 在 PROGRESS 顶部写"全部完成"并附最终证据,停下。
- **卡住跳过**:同一 DoD 项连续 3 轮不闭环、或撞上需人拍板的决策 → 标成 blocker 写进 PROGRESS,去做下一个能做的项。不停机空等,不在死磕点烧 token。
- **Phase 被卡死(终止)**:当前 Phase 剩下的未勾项全被 blocker 卡住、无项可推进 → 停下,把 blocker 清单留在 PROGRESS 顶部交给人。不要跳到后续 Phase 绕过被卡的前置。

## 单轮输出格式(追加到 PROGRESS.md)
```
## Round <N> — <日期>
- 目标:<Phase X / DoD 项原文>
- 动作:<实现摘要;派发的 subagent 及其结论>
- 验证:<命令 → 结果>(逐条)
- 勾选:<勾掉的 DOD 项 / 无>
- 遗留:<blocker 或下一轮建议起点>
```
